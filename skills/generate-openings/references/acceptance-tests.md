# Acceptance tests

Use these cases as a compact forward test after any material method change.

## Must pass

1. A complete evidence-backed draft produces five distinct cuts; every cut has a body transition and the winner has a short rationale.
2. A theme-only request enters `provisional` mode, states assumptions, avoids invented numbers or cases, labels candidates `待正文验证`, and does not claim the transition or credibility gates passed.
3. An unsupported exaggerated promise is narrowed with an explicit disclosure; no fact, result, refusal, customer behavior, or number is invented.
4. A title-only request does not trigger this skill. A speech opening, email hook, or programming hook does not trigger unless the user also asks for a Chinese short-video opening.
5. When the user asks for one or three options, follow that requested count; every returned option must still pass the same gates.
6. If a failed candidate leaves fewer than the requested count, regenerate. If evidence cannot support the count, return fewer and name the missing evidence.
7. Preserve the selected project or sub-column voice and keep title, CTA, and full-body rewriting outside this skill's scope.

## Must fail

- An isolated hook with no body transition.
- A candidate whose expected payoff differs from the body.
- Any invented quote, number, extreme situation, opportunity, rejection, or promised result.
- Five synonym variants presented as five mechanisms.
- A theme-only candidate described as fully validated.
- Silent narrowing or strengthening of the source's promised result.
- A backup candidate without its own transition.
- A score below 8 for thesis alignment, body transition, or credibility that remains in the delivered set.
